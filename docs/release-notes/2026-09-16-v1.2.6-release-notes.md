## 新增

- **手机的卡片现在能答选择题了**：当 agent 用 `AskUserQuestion` 问你（比如「接下来做哪个」），手机会收到一张**多选卡**——标题带会话名、描述行是问题原文 + `A=… B=… C=…` 完整选项、按钮只有 A/B/C（实测按钮文字预算仅约 2 个汉字，所以完整选项放描述行）。你点一下，选择就回注到那个会话，agent 直接接着干。协议：hook 以 `allow + updatedInput` 把答案写进工具输入。仅单个非多选题走此路径，多问题/多选题仍交回桌面。
- **「在跑」指令**：给机器人发「在跑」，回复当前正在运行的会话及各自已跑多久（按时间降序）。判据是心跳进程存活——注意 `turn_usage` 行只在回合结束后写入，不能用它判断"是否在跑"。
- **异常中止也会通知**：以前会话异常停止（关掉桌面端、崩溃、强杀）**完全静默**——Stop hook 在进程死亡时不触发，心跳又因"行不存在=还在跑"傻等到 4 小时上限。现在会推「🛑 桌面端已关闭，会话随之中止（中止时已运行 N 分钟）」，复核一次排除瞬时抖动。
- **卡片标题带会话名**：权限卡与选择题卡的标题形如「写周报 · 请求确认」，通知预览/聊天列表里一眼可辨；决定后会话名保留（原位更新是整卡替换，此前会把标题冲掉）。

## 修复

- **连接器 ws 掉线后永不恢复**（发布前检查时实测发现）：连接器进程活着、`/health` 正常返回，但 WebSocket 已断，而看门狗只判"HTTP 端口通不通"，于是永远认为在线、永不重启——现象是推送一路降级到群 webhook、卡片与微信指令全失效且不自愈（实测 40 秒无恢复，此前 README 所说"SDK 自动重连"在该场景不成立）。现在看门狗同时检查 `connected`/`target`，并在重启前清掉假死的旧进程（否则新实例会因单例锁直接退出）。真机验证：杀掉后 10.1 秒自愈，健康时不误重启。
- **安全审计修复（7 项）**：
  - `task_id` 路径穿越——`zc-../../state` 能过前缀检查并把决定文件写到 `decisions/` 之外，现加白名单正则
  - 本地 HTTP 端点零鉴权——任意本机进程可打，且 aiohttp 不校验 Content-Type，恶意网页可 drive-by POST 仿冒权限卡；现要求共享密钥头 + Origin 白名单
  - 连接器锁内容损坏时永久挡死启动（读锁异常即退出且不清理），现损坏/无 pid/pid 已死一律接管（pid 存活绝不抢）
  - `error` 回合迟落库被报成「✅ 任务完成」——状态未确认时改用中性标题，❌ 标题顺带带上 error_code
  - 降级文案把"连接器在线但拒绝"误报成"离线"，现区分两者并回填真实原因
  - `doctor` 在定时静默中报 PASS 误导排查，现如实 WARN 并显示剩余分钟
  - `state.json`/`aibot_config.json`/决定文件全部改原子写，避免并发读到半截 JSON（会让"静默中"的通知瞬间复活）
- **summary 超时默认 10 → 15 秒**：成功样本有 8.9s 与 12.0s 两档，10 秒会误杀慢摘要；15 秒兜住两档，远低于旧值 25 秒的白等。
- 顺带修：心跳里"回合结束"与"桌面端存活"的检查顺序颠倒（任务刚完成就关桌面端会误报中止）；`elapsed_min` 的隐式契约加固（异常返回 None 会崩掉心跳进程且无日志）。
