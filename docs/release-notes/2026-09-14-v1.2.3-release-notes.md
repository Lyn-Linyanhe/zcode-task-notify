## 修复

- **通知里一直没有耗时，出错也会显示「✅ 任务完成」**：`turn_usage` 的行是**回合结束后**才整体写入的（`duration_ms` / `error_code` 同批落库），而状态查询只在 `status == "running"` 时轮询——Stop hook 触发的那一刻行还不存在，`status` 是 `None`，轮询条件一次都不成立就直接返回。后果是耗时永远为空、出错永远按完成推送、取消永远不跳过（实测 46 条推送无一例外，而库里有 92 个 error 回合、73 个 cancelled 回合）。现在改为「等行出现、或等 running 变终态」，上限 `stop_status_wait_sec`（默认 60 秒）；实测行在回合 `completed_at` 后约 0.25 秒落库，正常情况等待不到 1 秒，取不到就降级为无耗时照常推送，绝不因为查不到而丢通知。

- **长任务 ⏳ 提醒从未触发过**：同一根因的另一处受害功能。心跳按「该会话最新一行」判断本轮是否还在跑，而最新一行永远是**上一个已结束的回合**，于是每次启动都秒退——实测 52 次启动 / 45 次秒退 / ⏳ 推送 0 次。现在把 UserPromptSubmit payload 里的 `turnId` 传给心跳，盯那一行：行不存在 = 本轮还在跑（起点用心跳自己的启动时刻估算），行出现且终态 = 结束退出。顺带修掉一个会让它变成噪音的问题：⏳ 必须先等满一个间隔再推（旧代码把 sleep 放在循环末尾，等于每条消息都会立刻收到一条「仍在运行」）；节拍改为 10 秒轮询，回合结束 10 秒内退出。

- **降级到群机器人时没有任何提示**：群机器人是单向通道，收到降级消息后回复指令、点卡片按钮都不会有反应。现在降级消息末尾自带一行 `⚠️ 通道降级`，写明原因（未配置智能机器人 / 未绑定用户 / 连接器离线 / 连接器拒绝），并提醒回复无效——「看到降级提示」本身就等于报警。

- **会莫名弹出一个终端窗口**：看门狗用 `.venv-aibot` 的 `python.exe` 拉起连接器时用了 `DETACHED_PROCESS`，但 venv 的 `python.exe` 只是启动器存根，它转手拉起真实解释器时不传这个标志，于是没有控制台的父进程让系统新建控制台，Win11 默认终端就渲染成一个 Windows Terminal 窗口（标题是存根路径），又因为连接器常驻而一直挂着。四组对照实验确认后统一改用 `CREATE_NO_WINDOW`。
